# 定时快照 session 与时间标签验证

验证日期：2026-10-01。本次是数据准备验证，没有重新训练策略或生成回测收益。
论文依据：PDF 第 3 页 §3.1 的定时 tick 与日内周期、第 4 页 Eq.(2)–(4)
的多尺度价格差，以及第 7 页 §4.2 的时间样本外划分。

## 实现与范围

- 新入口 `prepare_snapshot_dataset.py` 接受按时间排列的快照文件，按一个 session
  缓冲，生成 `snapshots.parquet`、`quality.json`、`quality.md`。
- 目标时刻必须精确存在，整个前瞻区间不得跨网格缺口、交易暂停、session 结束
  或显式切分。标签价格差和相对收益分别保存。
- 滚动特征在连续区间重启，30 格历史尚不完整时标记特征不可用，不补零。
- 当前 ESZ5 日历具有有限覆盖范围、夏令时规则、每日暂停及感恩节特殊 trade date。
  来源在 `config/cme_es_sessions_2025.json` 中保存；修改日历会改变报告中的哈希。
- 本入口尚未接入事件级训练和执行引擎；在线成熟、持仓、延迟仍需要后续迁移。

## 运行方式与追溯

在项目虚拟环境中，对每个日期执行下面的命令，再按时间合并三个产物：

```bash
python build_timed_snapshots.py --data-index data/ESZ5/index.json \
  --data-date 2025-09-21 --output /tmp/2025-09-21.parquet
# 对 09-22、09-23 同样生成快照，使用各自的新输出路径。
python prepare_snapshot_dataset.py \
  --snapshots /tmp/2025-09-21.parquet /tmp/2025-09-22.parquet /tmp/2025-09-23.parquet \
  --output-dir /tmp/esz5-session-check
```

本次最终验证产物位于 `/tmp/data-mining-session-validation-nktzs7u_/dataset-final/`，
原始数据、根目录旧 Parquet 和 `results/` 没有改动。
临时产物未提交；详细 JSON 保留源消息哈希、快照哈希、采样与质量元数据、
日历哈希、代码哈希及实际依赖版本。重新运行应选新的路径，工具拒绝覆盖既有目录。

## 性质验证

合成数据测试覆盖：精确价格差、目标格缺失、端点存在但中间缺格、特征重新预热、
未来价格变化不改写过去特征、切分边界等号清除、暂停与收盘隔离、
UTC 午夜跨文件拼接、批次不变性、夏令时、感恩节 trade date、跨 session 重启、
不同 Arrow 时间精度、默认拒绝前缀/降级输入、重复时间戳拒绝，以及失败不发布产物。
另验证浮点 flags 不得被截断为可靠事件。完整测试执行
`python -m unittest discover -s tests -v`，共 71 项通过。

最终发布核对结果以 PR 验证记录为准。单元测试通过只证明这些已定义的
工程性质，不证明论文的模型库、IRL、UCB/ARS 或完整多日实验已复现。
