## 小步开发约定

1. 先 `git fetch --prune origin`，检查 `git status -sb` 与待提交文件。
2. 新功能从最新 `origin/main` 创建分支；同一尚未合并的功能可在其分支上继续小步提交。
3. 每次只处理一个明确改进，代码和关键测试用中文解释，完成相应验证后提交、发布、汇报。
4. 已合并的 PR 分支不再用于新工作。尤其压缩合并之后，不用旧提交数量判断代码差异。
5. 功能分支发布后通过 PR 审阅合并；`main` 与功能分支可以暂时不同，但各自的本地与远程应一致。
6. 本地备份中的独有代码先保留；清理历史分支应单独确认其用途和备份，不依靠强制推送消除差异。

## 数据和结果放在哪里

- GitHub：代码、测试、论文、说明文档和已明确提交的实验结果。
- Hugging Face：[新增数据集](https://huggingface.co/datasets/badraldine/datamining_hft_SUFE)。
- 本地 `data/`：下载的数据、索引和 Parquet；由 `.gitignore` 排除，目录不被跟踪是预期状态。
- 本地 `/tmp/`：小窗口验证的临时 JSON、报告和看板，避免覆盖正式实验结果。

根目录两份旧 Parquet 已经纳入版本管理，本轮保持原状，以保证现有实验和 GitHub CI
仍然能够运行。忽略 `data/` 不会删除本地数据，也不会删除仓库中已经跟踪的文件。

## 发布方式

当前环境的 Git 命令行可以读取远程仓库，但没有可用于 HTTPS 推送的身份凭据。
本轮使用已连接的 GitHub 工具创建提交和更新功能分支，再 fetch 回本地对齐。
通过这种方式发布时，会核对文件树与实际验证的本地内容完全相同；不把不同提交
元数据造成的哈希差异当成代码冲突。后续若配置好命令行身份验证，可直接使用 Git push。
