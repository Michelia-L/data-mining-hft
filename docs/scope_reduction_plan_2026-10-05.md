# 10分钟课程展示的项目瘦身计划（2026-10-06）

本文沿用原计划路径，替代2026-10-05版的五个后续PR路线。当前目标是让经济类专业组员看懂项目、制作PPT和讲稿、回答老师追问。课程展示以解释核心机制和如实报告结果为完成标准，不继续扩成研究平台。

本轮只制定计划；文件删除、代码合并、测试退出和PPT制作属于下文待执行工作。新命令和目标目录均是计划，不是当前已经可用的入口。

## 1. 交付目标和停止条件

建议题目：**从固定模型到动态选模型：FMATO的核心机制与课程部分复现**。

全组只需围绕一个问题准备：

> 在相同交易与成本条件下，根据多尺度成交后评价动态选择预测模型，是否比固定模型和简单集成更有效？

最终只要求三份组员阅读材料：README.md说明项目和阅读顺序；presentation.md包含逐页PPT要点、讲稿和问答；final_replication_report.md提供简短的方法、实验和结果依据。组员不必阅读源代码、原始JSON、配置矩阵和历史PR。

完成标准是8页正文PPT、约9分20秒讲述、40秒机动、3页备用材料、一个无需行情的结果核对命令。主线代码仍能解释并支持核心回放，完整数据重跑交给维护者，不要求全组安装环境或课堂重训。

不再新增ME/ARS变体、专家来源搜索、奖励约束搜索、报价年龄搜索、品种、看板、通用框架或研究诊断。目录数量不是硬指标，不为合并文件重写已正确的算法。清理最多再用两个执行PR，可以合并为一个；不把五轮重构或全季度回测当作展示前提。

## 2. 当前负担与核心范围

main基线0338afc包含21个根目录Python入口、22份配置、23个测试文件、21份docs文档；README为628行，最终报告为668行。这些材料超过了10分钟展示需要。

唯一方法链路是：

~~~text
真实时间盘口 → 轻模型库 → 成交后多尺度评价
                         ↓
                  历史校准学习评分权重
                         ↓
             UCB选模型 → 交易回放 → 扣成本比较
~~~

讲述时区分两种学习：奖励权重在历史校准阶段拟合后冻结；UCB在后续回放中根据已经成熟的反馈调整模型选择。不能讲成奖励权重在测试期间不断重学，也不能讲成强化学习直接输出订单价格和数量。

保留的主比较仅有五项：现金、固定库候选、均值集成、等权OE-UCB、学习权重OE-UCB。等权UCB是必要对照，可以区别人工评分与学习评分；不能只剩学习组和现金，再把差异全部归功于IRL。

主线继续使用既有12个模型、七尺度、5分钟期间、同一执行与成本规则、sum_only约束和库内专家来源。不同特征/历史期、候选身份与周更新不改变。全候选来源、ME、双ARS、单尺度赋权退出默认回放；其已有失败和结果仍由原快照保留。

500ms是快照网格间隔；500/1000/2000ms是三个既有报价年龄口径。正文结果同时列三列，保留严格口径阻断和不利结果，不根据收益选择某一列为默认。它们是现有证据的质量边界，不继续扩展参数组合。

## 5. tests目录与最低限度的核对

同意最终课程版可以没有tests/。测试目录不是组员的阅读任务，也不作为展示内容。瘦身期间先保留，用于发现删除依赖或合并入口造成的错误；完成必要核对后，删目录并同步CI。

最终只保留一个维护者使用的check_project.py，检查范围明确：

| 检查 | 验证什么 | 能否证明算法有效 |
| --- | --- | --- |
| 展示数字核对 | 摘要、图和讲稿金额来自固定快照；三年龄、现金0、阻断null均一致 | 不能 |
| 简短账本核对 | 净利=毛利−成本，逐日与累计一致，费用单位正确 | 不能 |
| 一次核心合成检查 | 决策不提前使用未来价格，反馈不早于最长前瞻成熟；基本执行完成 | 只支持该小样本性质 |
| 入口和引用检查 | 新入口可导入、保留文件可访问，CI不再读取已删除旧数据 | 不能 |

结果读取核对只依赖标准库；核心合成检查使用项目数值环境。CI保留这两类检查，不下载78天行情，也不训练完整季度。当前测试中与因果性、成熟和账本相关的少量性质可复用，不能把23个文件原样搬进scripts/换个名字。

已有verify_final_delivery.py不能直接沿用原语义：它固定36项当前源码哈希、七份文档和完整收益表，会阻止正常清理。处理顺序是先在原版本运行并记录通过，再建立课程核对。新核对固定三份快照和图的身份，核对课程摘要；历史源码提交保持原记录，Git对象核对列为可选。

新代码产生新结果时记录新的源码/数据身份；历史快照始终绑定历史提交。不能修改旧快照的源码哈希来迁就新目录。新的简化核对不得声称重新证明原行情真实性或全部成交因果性。

## 6. data目录和“全部数据”的边界

目前data/ESZ5索引含78个UTC日期、714385685条记录，范围为2025-09-15至2025-12-15（不含末日）。3个日期标记degraded，不能默认为质量合格。78份Parquet在本地均存在；UTC文件日期不等于交易session。

现有报告涉及21个不同交易session，原开发和后段各有七个动态评价session。讲述建议用最后七日冻结复核为主表，原开发结果作为备用背景，避免把两批结果混成一次回测。

本次“只保留新数据路线”指旧ES/Brent文件及其产物退出当前版本；不能把现有七日结果改称“全季度回测”。不建议为了10分钟展示临时补全78天。

若“必须使用全部合格新数据”仍是硬要求，需要在收益运行前另行固定完整session覆盖、训练/校准/评价切分、周更新与质量排除规则，分批运行并保存新结果身份；它是额外实验工作，不是删除旧文件或制作PPT能够自动完成的内容。应在替换主结果之前完成，不能先删旧证据再补一个来历不清的新表。

## 9. 组员必须掌握的问答

| 老师可能问 | 建议回答要点 |
| --- | --- |
| 强化学习的动作是什么？ | 选择一个预测模型；不是让神经网络直接给出完整订单。 |
| IRL和UCB分别做什么？ | IRL近似学习多尺度打分权重；UCB根据已成熟评分动态选模型。 |
| 奖励是不是赚钱多少？ | 奖励是未来中间价差的组合，单位价格点；利润扣点差、滑点、手续费，单位美元。 |
| 为什么奖励用了未来价格却没有前视？ | 未来价格只用于离线历史校准和到期评价；决策与在线更新必须等信息真的到达。 |
| 所谓专家可靠吗？ | 是校准候选中净利最高者，不是盈利高手；现有库内专家仍亏损，成熟样本很少。 |
| 为什么没有盈利？ | 当前信号、成本、稀疏反馈和替代市场共同限制；现有实验没有识别各原因的独立贡献。 |
| 为什么没有全量数据回测？ | 新数据总量和实际实验范围不同；我们如实展示选定的开发与冻结复核阶段。 |
| 为什么只讲OE-UCB？ | 10分钟主讲核心闭环；ME和ARS已有证据保留，但不是本次讲述重点。 |
| 现金0与阻断有什么区别？ | 现金是已运行且不交易；阻断是条件不满足而没有收益观察，不能补成0。 |
| 固定模型是事后挑的吗？ | 没有，固定候选身份事先确定，按同一周规则更新参数。 |
| 原论文结果比我们的好，复现失败了吗？ | 我们实现了核心结构，但市场、历史、执行和优化器不同；不能声称等价复现，也不能据此否定原论文。 |
| 长期奖励等于持仓一小时吗？ | 不等于。奖励的观察前瞻、选择期间、执行延迟和实际持仓是不同时间量。 |
| 这些结论有统计显著性吗？ | 样本短，策略日并非独立样本；我们报告有限观察，不作长期或显著性推断。 |
