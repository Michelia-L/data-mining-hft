# 项目收敛与主线重构计划（2026-10-05）

## 1. 决策

当前仓库已经完成一轮较完整的 FMATO 部分复现探索，但实验轴、入口和验证文档继续增加后，项目的主研究问题开始被工程覆盖面淹没。

从本计划开始，后续开发不再以“尽可能补齐所有论文变体”为默认目标，而改为围绕一个可解释、可复核的核心问题收敛：

> **在因果的真实时间盘口回放中，基于多尺度 OE 奖励的 UCB 动态模型选择，能否在同一执行与成本口径下优于固定模型和现金基线？**

本次 PR 只统一项目边界、导航和后续开发规则，不删除历史代码、不修改已冻结实验结果，也不重新解释既有负结果。

## 2. 为什么现在要收敛

当前最终报告已经给出足够清楚的工程结论：

- 因果定时快照、真实时间执行、周模型版本与反馈成熟链路已经能够被审计；
- 多尺度奖励、有限策略学习和动态选择已经有完整或受阻状态记录；
- 冻结复核并未显示学习奖励带来稳定收益改善；
- 继续横向增加 ME/OE、UCB/ARS、quote age、奖励约束、专家来源等组合，会显著增加代码与解释成本，但不一定增强核心结论。

因此，后续工作的优先级应从“增加覆盖面”切换为“减少分支、提高主线清晰度、让组员能用一条路径理解和复核项目”。

## 3. 唯一主线

后续 README、演示、答辩和默认运行路径都围绕下面一条链路组织：

```text
原始盘口
  ↓
500ms 因果快照
  ↓
session / feature / label 数据集
  ↓
按周更新的轻模型库
  ↓
OE 多尺度奖励学习
  ↓
5 分钟 Period UCB 模型选择
  ↓
统一真实时间执行器
  ↓
现金 / 固定模型 / 均值集成 对照
  ↓
净收益、成本、成熟反馈与选择行为分析
```

这条主线保留 FMATO 最关键的闭环：**模型作为动作 → 奖励学习 → 在线模型选择 → 因果交易评价**。

## 4. 范围分层

### 4.1 Core：继续维护并用于最终讲述

以下能力属于主线，后续重构应优先保留、合并入口并减少重复实现：

| 能力 | 当前实现 |
| --- | --- |
| 因果定时快照 | `build_timed_snapshots.py`, `src/timed_snapshots.py` |
| session / 时间标签数据集 | `prepare_snapshot_dataset.py`, `src/snapshot_dataset.py` |
| 按周轻模型库 | `run_weekly_library.py`, `src/weekly_library.py` |
| OE 奖励与权重学习 | 现有 OE / reward 模块中与主线直接相关的部分 |
| 固定期间 UCB | `run_period_ucb.py`, `src/period_ucb.py` |
| 真实时间执行与成本 | `src/time_execution.py` 及主线调用路径 |
| 必要基线 | 现金、固定 Ridge、固定库候选、均值集成 |
| 最终结果说明 | `final_replication_report.md`, `results/final_report/` |

### 4.2 Frozen evidence：保留证据，但原则上不再扩展

以下内容已经为研究判断提供过证据。它们继续保留并可复核，但除非发现正确性问题，不再新增参数轴或新变体：

- snapshot age 审计与多周 readiness；
- expert scope、reward constraint 等可表示性/边界审计；
- four combinations；
- frozen ablation；
- multiweek dynamic OE；
- 既有最终交付验证与对应结果快照。

“冻结”不等于无效，也不代表删除；含义是它们不再决定仓库的默认使用方式。

### 4.3 Legacy / appendix：退出主线

以下内容保留为历史过程或附录材料，但不再出现在 Quick Start、默认运行链路或最终方法主图中：

- 事件级 `run_experiments.py` 及早期事件 UCB / Shadow ARS；
- ME 主线及 ME/OE 四组合扩展；
- `recent` / `matured` 两套 ARS 工程解释；
- 三种 quote age 同时作为主实验轴；
- simplex / signed-box / sum-only 同时作为主实验轴；
- 仅用于历史演进的中间 runner、旧报告和 dashboard。

后续可以通过独立 PR 将这部分移动到 `archive/` 或 `docs/legacy/`，但迁移不得破坏既有证据链接。

## 5. 主线默认口径

为了避免“每个维度都保留多个版本”，后续 canonical profile 应只有一套默认口径。现有正式结果在本 PR 中不变；下面是后续重构的目标默认值：

- 时间单位：500ms 定时快照；
- quote freshness：以 500ms 严格口径作为默认，不按收益反选；
- 模型库：保留当前“算法 × 特征组 × 历史长度”的轻模型库结构，不再额外扩模型家族；
- 奖励：OE 作为唯一主奖励路径；
- 奖励尺度：暂沿用当前冻结结果的七尺度定义，是否进一步缩短只允许在单独方法 PR 中讨论；
- 权重约束：主线只保留一个预声明约束；现有冻结执行口径优先作为基线，其他约束降为敏感性材料；
- 选择器：Period UCB 作为唯一主动态选择器；
- 对照：现金、固定模型、必要的简单集成；
- 评价：真实时间、奖励成熟后更新、统一成本与执行条件。

本计划不把上述工程设定包装成论文唯一规定；论文未公开或存在歧义的地方继续明确标注为项目假设。

## 6. 后续 PR 顺序

本 PR 是“总控 PR”，后续改动按下面顺序拆分，避免一次性大删造成难审：

1. **建立 canonical 入口**  
   将主线整理成一个默认配置和一个统一 runner；现有底层模块先复用，不急于重写。

2. **缩短 README 与导航**  
   Quick Start 只展示 canonical 入口；完整实验史改由文档索引进入。

3. **冻结并迁移 legacy 入口**  
   将旧 runner、旧 dashboard 和历史方法说明移动到明确的 legacy/archive 区域；保留 Git 历史与结果引用。

4. **收敛测试层级**  
   核心 CI 优先验证因果性、reward maturity、UCB 更新、账本与 canonical pipeline；legacy 测试保留但不阻碍理解主线。

5. **收敛最终报告表达**  
   主文围绕一个研究问题和少量关键表图；组合矩阵、失败分支和敏感性放附录或证据索引。

## 7. 新功能准入规则

从本计划合并后，新增实验或算法变体必须同时满足：

1. 它直接回答核心研究问题，而不是只增加覆盖面；
2. 它能替换或删除一个现有分支，或有明确的课程验收必要性；
3. 它不会让默认入口、默认配置或最终讲述重新出现多套平行方法。

如果只是“论文里还有一个变体没有做”，但不会改变核心判断，默认不做。

## 8. 本次 PR 不做什么

- 不删除任何历史代码、结果或验证文档；
- 不重跑训练或回测；
- 不改变现有结果数字；
- 不把负结果改写为正结论；
- 不在本 PR 中决定新的 reward horizon；
- 不声称当前实现等价于论文完整生产系统。

## 9. 完成标准

后续收敛完成时，新的组员应当能够：

- 5 分钟内从 README 说清楚项目唯一研究问题；
- 只通过一个默认入口理解完整数据到评价链路；
- 区分 core、frozen evidence 与 legacy；
- 在不阅读全部历史 PR 的情况下解释主要结果和限制；
- 需要追溯时，仍能找到全部原始实验与负结果证据。

这比继续增加策略数量更符合当前阶段的课程交付目标。
